# Environment detection after the scanner benchmark

The local scanner now tokenizes JavaScript/TypeScript code instead of matching environment access text on individual lines. It skips comments, quoted strings and supported regex literals; handles multiline direct accesses, Vite accesses, destructuring and literal defaults; and resolves literal first arguments passed to simple named local functions that forward that parameter to an environment lookup. Modified parameters and duplicate function declarations are not resolved. Dynamic accesses remain warnings even when literal calls are found. No source is executed and no external parser dependency is required.

Python os.environ indexing is required evidence; explicit non-None literal getenv/get defaults are optional evidence. Simple JavaScript bindings with nearby explicit missing-value throws provide required evidence. These are source-level requirements, not proof the code executes at startup. Conflicting evidence remains uncertain.

Shell assignment discovery no longer interprets example assignments inside echo text as local definitions. Explicit missing-variable guards that append to a missing-input list are recognized. Empty shell fallbacks alone do not prove optionality. Requirements supported only by shell scripts are marked as script-scoped; missing values require review rather than blocking an unrelated app launch as definitely missing.

Scoped inspection still excludes independent nested projects from its editable form and value resolution. It now includes a separate, read-only repositoryInventory of names/evidence from nested projects. The inspect_project_environment_inventory API provides that bounded inventory directly; it never resolves values or asserts launch readiness. The modal displays this inventory separately and distinguishes script requirements. Source defaults no longer receive the misleading label “schema declares a default.”

Both inventory modes keep file, byte, variable and response evidence limits, exclude dependency/build directories, and reject symlink files. Helper analysis is capped at 32 dynamic accesses per file. Metadata contains names and evidence, not default values or actual environment values.

Validation: the reviewed Soil Science app/shared corpus now yields all 11 expected names when components are combined; the viewer yields all 3 (one app variable and two deployment variables). All 8 syntax fixture names are found with no false positives. HypoCompass remains a clean zero-input control. This is a small targeted corpus, not a universal accuracy claim.

Remaining limits: lexical analysis is not a complete language parser or call graph; arbitrary wrappers, shadowing and computed keys cannot be reliably resolved. Template expression accesses produce warnings. Runtime feature reachability, selected-command script mapping, Vite envDir and development-versus-production loading remain separate work; this change does not claim to fix them. No merge or deployment is included.

Component inspection now discovers its enclosing Git repository (or accepts a validated explicit root for non-Git projects), performs the bounded whole-repository inventory, and links root example evidence to matching selected-component variables. The form explicitly shows repositoryRoot and repositoryExamples; other components stay in the separate inventory. This reads .env.example as evidence, not as actual values. It still does not resolve Vite envDir for actual dotenv loading.

The modal now renders displayVariables in four visible groups: required for this app, optional, other apps/tasks, and unresolved. Scoped variables carry blocksContinuation; unreferenced deploy-named scripts are treated as other tasks unless mentioned by start/dev package scripts. Repository-only names are read-only in this component's form. Shared-package applicability is unresolved, not silently asserted irrelevant. Grouped other-task variables do not pause automatic continuation; missing required app inputs do. Diagnostic warnings are expandable. This is conservative source/package-script classification, not full launch call-graph analysis, and does not change the documented envDir/mode limitation.
